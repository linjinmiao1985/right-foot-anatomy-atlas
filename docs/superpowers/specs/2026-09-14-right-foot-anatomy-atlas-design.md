# 右足解剖图谱 MVP - 设计规格

## 概述

构建一个交互式的右足解剖 3D 可视化 Web 应用，采用 Visible Body 风格，专注于足部解剖结构的教育展示。

## 产品目标

- 提供清晰、交互式的右足解剖结构 3D 可视化
- 支持多层次解剖结构切换（骨骼、肌肉、神经、血管）
- 显示中英文对照的解剖学名称和简短说明
- 保持简洁的 MVP 范围，专注核心交互体验

## 用户故事

1. **作为医学学生**，我希望能够旋转和缩放 3D 右足模型，以便从不同角度观察解剖结构
2. **作为学习者**，我希望点击特定结构时能看到其中文和拉丁文名称及简介，以便加深理解
3. **作为用户**，我希望能够独立切换不同层的可见性，以便专注于特定系统的学习
4. **作为教育者**，我希望应用清楚标明占位资源，以便理解当前实现的局限性

## 功能需求

### 核心功能（必须）

#### F1. 3D 交互视口
- 使用 React Three Fiber 渲染 3D 场景
- 支持轨道控制（OrbitControls）：旋转、缩放、平移
- 默认视角：右侧视图，展示足部全貌
- 背景：深色临床中性色调

#### F2. 结构分层系统
- 四个独立图层：
  - 骨骼（bone）- 米色/象牙色
  - 肌肉（muscle）- 红色系
  - 神经（nerve）- 黄色
  - 血管（vessel）- 深红色
- 每层可独立显隐
- 隐藏层的结构不可点选

#### F3. 图层切换面板
- 四个独立开关：骨骼 / 肌肉 / 神经 / 血管
- 显示每层的颜色指示
- 对于占位几何体，显示「占位」徽章

#### F4. 结构信息面板
- 点击结构显示：
  - 中文名称（nameZh）
  - 拉丁文名称（nameLa）
  - 所属图层
  - 简短中文说明（summaryZh）
  - 如果是占位，显示「占位」标记
- 未映射结构显示：「未标注结构」
- 按 Escape 或点击空白处取消选择
- 可选：悬停工具提示显示名称

#### F5. 结构选择与高亮
- 点击网格选中结构
- 选中状态：发光/边缘高亮效果
- 相机平滑聚焦到选中结构

### 数据需求

#### D1. 解剖结构数据
- 文件：`src/data/structures.json`
- 最少 15 个结构，覆盖所有四层
- 结构定义：
```json
{
  "id": "calcaneus",
  "meshNames": ["Calcaneus_R"],
  "layer": "bone",
  "nameZh": "跟骨",
  "nameLa": "Calcaneus",
  "summaryZh": "足部最大的跗骨，形成足跟，承担站立时的主要负重",
  "placeholder": false
}
```

#### D2. 3D 资产
- 首选：开源可商用的足部解剖 glTF 模型（需明确授权）
- 备选：示意性占位几何体
  - 骨骼：盒状/胶囊
  - 肌肉：拉长的几何体
  - 神经：细管
  - 血管：略粗的管
- 清单文件：`public/models/right-foot/manifest.json`

### UI/UX 需求

#### U1. 布局
- 全屏 3D 视口
- 左上：标题「右足解剖图谱 · MVP」
- 右侧：图层切换面板（固定位置）
- 右下：结构信息面板（有选择时显示）

#### U2. 视觉风格
- 深色临床风格（类似医学应用）
- 主色调：深灰、白色文字
- 强调色：青色（用于高亮/选中状态）
- 字体：无衬线，清晰易读
- 中文优先显示，拉丁文为辅

#### U3. 交互反馈
- 鼠标悬停：光标变为指针（可点击网格）
- 点击：即时高亮 + 面板展开
- 图层切换：平滑过渡（300ms）
- 加载状态：进度指示器或加载消息

### 技术约束

#### T1. 技术栈
- **构建工具**：Vite 5.x
- **框架**：React 18.x
- **语言**：TypeScript 5.x（严格模式）
- **3D**：three.js + @react-three/fiber + @react-three/drei
- **测试**：Vitest + @testing-library/react
- **样式**：CSS Modules 或内联样式

#### T2. 浏览器支持
- 现代浏览器（Chrome、Firefox、Safari、Edge 最新两个版本）
- 需要 WebGL 2.0 支持

#### T3. 性能目标
- 初始加载 < 3 秒（网络正常）
- 60 FPS 交互（所有层显示）
- 网格数 < 100（占位实现）

### 非功能需求

#### N1. 代码质量
- TypeScript 严格模式，无 any
- 组件单元测试覆盖核心逻辑
- 清晰的代码组织和命名

#### N2. 文档
- README：运行说明、技术栈、免责声明、资产许可
- 代码注释：复杂逻辑和公共 API
- 明确标注占位资源

#### N3. 可扩展性
- 易于添加更多结构
- 为未来扩展到踝关节预留架构
- 支持替换占位几何体为真实模型

## 风险与缓解

### R1. 3D 资产获取困难
- **风险**：无法找到合适的开源足部模型
- **缓解**：使用占位几何体完成 MVP，UI 明确标注
- **影响**：教育价值降低，但核心交互流程完整

### R2. 性能问题
- **风险**：复杂模型导致帧率下降
- **缓解**：简化几何体、使用 LOD、优化渲染
- **影响**：用户体验受影响

### R3. 准确性要求
- **风险**：医学准确性审查需求
- **缓解**：清晰的教育免责声明，强调"非临床诊断"
- **影响**：使用场景受限

## 成功指标

- 应用可正常构建和运行
- 核心交互流程顺畅
- 代码质量达标（测试通过、类型安全）
- 文档完整诚实
- 为未来迭代奠定良好基础
